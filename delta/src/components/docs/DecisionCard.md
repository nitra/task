## Огляд

Файл керує процесом прийняття рішень через перехід між стадіями `identity`, `approved` та `decision`. Він визначає шлях від визначення суб'єктів через `mandatesDir` до фінального підтвердження через `quorum-signed`.

## Поведінка

Процес починається з вибору варіанта, що активує питання квізу про наслідки. Вибір можна скинути для зміни варіанта без впливу на стан файлу на диску.

Відповідь на питання веде до двох сценаріїв: неправильна відповідь запускає навчальний режим для розгортання контексту, залишаючи гейт відкритим; правильна відповідь на проміжному етапі відкриває наступне питання, а на фінальному — завершує квіз і створює підписаний approval.

Teach-back-переказ використовує механізм підтвердження через транскрипт. Якщо LLM недоступна, спроба вважається помилкою без фіксації результату. У разі розуміння проводиться фіналізація та підпис, у разі нерозуміння — запускається режим пояснення для нової спроби.

## Публічний API

- decision — формує фінальний результат на основі перевірки кворуму та наявності підписів
- mandatesDir — надає шлях до директорії, де зберігаються мандати
- identity — забезпечує унікальну ідентифікацію суб'єкта або документа
- approved — вказує на стан схвалення
- quorum-signed — підтверджує відповідність зібраних підписів вимогам кворуму для прийняття рішення

## Гарантії поведінки

- Власних операцій запису (ФС/БД) у файлі немає; виклики імпортованих модулів можуть писати.
