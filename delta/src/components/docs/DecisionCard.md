## Огляд

Файл керує процесом прийняття рішень та перевірки статусу через `identity`, `approved` та `quorum-signed`. Він дозволяє визначати напрямок через `decision` та керувати директорією через `mandatesDir`.

## Поведінка

Процес починається з передачі об'єкта `decision`, параметрів `mandatesDir` та `identity` для ініціалізації стану картки. Користувач обирає варіант із доступних опцій, що запускає генерацію квізу. Якщо рішення потребує кворуму, процес переходить у режим колективного підпису: кожен учасник проходить власний квіз, а стан кворуму відображає прогрес підписантів та можливі розбіжності.

Під час проходження квізу відповіді призводять до різних наслідків: правильна відповідь на останньому питанні фіналізує процес, генеруючи результат підпису. Якщо квіз ще не завершено, користувач переходить до наступного питання. Неправильна відповідь активує навчальний режим із мікроуроками або розгортанням контексту для глибшого розуміння.

Після успішного завершення квізу:
- Для одноосібних рішень активується стан `approved`, що відображає фінальний результат.
- Для кворумних рішень активується стан `quorum-signed`, що сигналізує про виконання власної частини зобов'язань без автоматичного закриття всього рішення.

Зміна варіанту можлива лише до моменту фіксації підпису. Результати підпису та зміна станів передаються через події `approved` або `quorum-signed` для синхронізації з чергою рішень.

## Публічний API

- decision — фіксує остаточний результат розгляду пропозиції
- mandatesDir — надає доступ до каталогу з мандатами
- identity — встановлює зв'язок із суб'єктом або об'єктом
- approved — засвідчує стан схвалення
- quorum-signed — підтверджує наявність достатньої кількості підписів для досягнення кворуму
