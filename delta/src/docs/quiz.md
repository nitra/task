## Огляд

Модуль реалізує генерацію навчальних квізів та режим teach-back: від створення питань через `generateQuiz` з автоматичним перемиканням на `fallbackQuiz` до оцінки переказу знань через `buildTeachBackEvalPrompt` та `callLlmTeachBackEvaluator`. Система забезпечує роботу з конфігураціями через `defaultLlmConfig`, а також серіалізацію та відновлення даних за допомогою `formatQuizFile`, `parseQuizFile`, `formatTeachBackFile` та `parseTeachBackFile`.

## Поведінка

Поведінка системи базується на використанні конфігурацій за адресою http://127.0.0.1:8080, що визначаються через defaultLlmConfig. Процес генерації квізів (generateQuiz, generateStandardQuiz) починається з формування промптів через buildQuizPrompt на основі даних decision-request. Система намагається виконати запити через callLlmQuizGenerator або callLlmStandardQuizGenerator; якщо ендпоінт недоступний або відповідь невалідна, автоматично активуються детерміновані фолбеки: fallbackQuiz, fallbackSecondaryQuestion або fallbackStandardQuiz. При виникненні конфлікту між ідентифікатором моделі та рекомендованим варіантом, система примусово переходить на фолбек. Для повторних заходів використовується rephraseQuestion, що дозволяє змінювати формулювання без зміни варіантів відповідей.

Для режиму teach-back використовуються спеціалізовані інструменти: teachBackPromptText надає підказку для користувача, buildTeachBackEvalPrompt готує контекст для оцінки, а callLlmTeachBackEvaluator виконує аналіз переказу. Якщо локальна модель недоступна, використовується TEACHBACK_UNAVAILABLE_MESSAGE, оскільки для цього режиму не передбачено детермінованого фолбеку.

Робота з файлами забезпечує повний цикл збереження та відновлення стану. formatQuizFile та formatTeachBackFile серіалізують дані у markdown згідно з правилами, що описуються у config.json та response.json. Для відновлення стану з файлів використовуються parseQuizFile та parseTeachBackFile, які підтримують як сучасні структури з масивами питань, так і legacy-формати.

## Публічний API

- buildQuizPrompt — Формує user-промпт із тіла decision-request і обраного варіанта.
- callLlmQuizGenerator — Викликає локальний OpenAI-сумісний ендпоінт для генерації квіз-питання.
Мережева/парсингова помилка, неочікувана форма відповіді, чи недоступний
ендпоінт — повертає `null` (не кидає): виклик тримає фолбек як штатний,
не винятковий шлях («квіз ніколи не пропускається»).
- fallbackQuiz — Детермінований фолбек-генератор (ендпоінт недоступний): питання й варіанти
будуються з самих варіантів decision-request, без LLM. Правильна відповідь
— заголовок+тіло обраного варіанта; дистрактори — інші варіанти файлу
(доповнені нейтральним «жоден з наслідків вище», якщо варіантів < 2).
- generateQuiz — Генерує one-tap квіз для обраного варіанта: спершу LLM, потім фолбек.
Валідує інваріант `generated_by ≠ recommended_by` (mandates.md,
«конфлікт інтересів у промпті») — якщо LLM-ідентифікатор моделі якимось
чином збігся з рекомендувальником, примусово переходить на фолбек.
- callLlmStandardQuizGenerator — Викликає локальний ендпоінт у режимі `standard` (2 питання одним
викликом) — той самий контракт помилок, що {@link callLlmQuizGenerator}:
мережева/парсингова помилка чи невалідна форма повертає `null`, не кидає.
- fallbackStandardQuiz — Детермінований фолбек-генератор режиму `standard` (2 питання, ендпоінт
недоступний): перше — {@link fallbackQuiz} (наслідок обраного варіанта),
друге — {@link fallbackSecondaryQuestion} (ціна/межа наслідків) — різні
боки розвилки, той самий інваріант «квіз ніколи не пропускається».
- generateStandardQuiz — Генерує `depth: standard` квіз (2 питання) для обраного варіанта: спершу
LLM, потім фолбек — той самий `generated_by ≠ recommended_by` інваріант,
що {@link generateQuiz} (one-tap).
- rephraseQuestion — Перефразовує формулювання питання для повторного заходу після
неправильної відповіді («Повторне питання після кожного шару... те саме
або перефразоване LLM-ом, якщо ендпоінт живий» — docs/specs/
260809-delta-app.md, «Обсяг M2», п.3). Best-effort: мережева помилка,
недоступний ендпоінт, порожня чи незмінена відповідь — повертає `null`,
викликач лишає попередній текст питання (варіанти/правильна відповідь
НІКОЛИ не міняються перефразуванням — лише текст самого питання).
- buildTeachBackEvalPrompt — Формує user-промпт для оцінки переказу — той самий контекст, що
{@link buildQuizPrompt}, плюс сам переказ власника.
- callLlmTeachBackEvaluator — Викликає локальний ендпоінт для ОЦІНКИ переказу (не генерації питання —
teach-back немає питання, лише вільний текст власника проти
decision-request). Той самий контракт помилок, що {@link callLlmQuizGenerator}:
мережева/парсингова помилка, недоступний ендпоінт, чи невалідна форма
відповіді повертає `null`, НЕ кидає — але, на відміну від Q&A-квізу, `null`
тут означає «teach-back недоступний», а НЕ «перейти на фолбек» (заголовок
секції вище — свідомо немає детермінованого фолбека).
- formatQuizFile — Серіалізує квіз-стан у markdown точно за форматом mandates.md
(`schema_version` перше поле). Приймає або legacy-форму (`attempts` —
єдине питання, той самий формат, що M1) або узагальнену `questions`
(масив питань квізу — `depth: standard`, і/або підмішане spaced-repetition
«Питання N (повторення)»); `attempts` без `questions` трактується як одне
питання без повторення — байтово той самий вихід, що M1 (backward-compat).
- parseQuizFile — Розбирає квіз-файл назад у структурований стан (CLI-показ, тести,
round-trip перевірка формату). Повертає ОБИДВІ форми: `attempts` —
плаский список УСІХ спроб УСІХ питань (backward-compat з M1 для
one-question квізів) і `questions` — згруповані за номером питання, з
прапорцем `repetition` на кожному (spaced-repetition-питання).
- formatTeachBackFile — Серіалізує стан teach-back-квізу в markdown — контракт задачі M5: «##
Переказ (teach-back)» з транскриптом + «### Оцінка локальної моделі» з
вердиктом, для КОЖНОЇ спроби (перша неправильна спроба лишається в
файлі — той самий інваріант «фейл ≠ покарання», що {@link formatQuizFile}).
- parseTeachBackFile — Розбирає teach-back-квіз-файл назад у структурований стан — той самий
frontmatter-парсинг, що {@link parseQuizFile}, тіло — власний формат
(«## Переказ (teach-back)» блоки, не «## Питання N»).
- defaultLlmConfig — надає базові налаштування для роботи з мовною моделлю.
- teachBackPromptText — формує інструкції для генерації зворотного зв'язку з користувачем.
- TEACHBACK_UNAVAILABLE_MESSAGE — повідомляє, що teach-back недоступний без локальної моделі — рішення лишається відкритим. Незворотне рішення не

Налаштування поведінки базуються на файлах config.json та response.json. Доступ до сервісу здійснюється через http://127.0.0.1:8080.
