## Огляд

Тонкий шар над `llm-cascade` із окремого репо `nitra/7n-rules` у `llm-lib/crates/llm-cascade`, який дає owner лише дві незалежні точки входу: `one_shot` і `one_shot_acp`. Тут немає драбини ACP → local → cloud і немає рішення про те, чи дозволена ACP-підписка на цьому вузлі: цю композицію разом із policy `external_comms` збирає JS-шар `owner/src/composables/use-llm-cascade.js`. Файл свідомо без залежності на Tauri, тому `cargo test -p owner-llm` виконується без перезбірки Tauri-застосунку. Кожен `one_shot_*` працює за fail-fast принципом як рівно один виклик, а помилки обробляються fail-safe без винесення винятків назовні.

## Поведінка

one_shot і one_shot_acp утворюють дві незалежні точки входу до owner-LLM: перша веде запит у local/cloud каскад, друга — у локально залогінений ACP-агентський CLI. Обидві працюють fail-fast: спершу відсіюють невалідний режим виклику, а далі або одразу повертають помилку, або передають керування до зовнішнього виклику без додаткових шарів маршрутизації.

one_shot спочатку нормалізує тир і підставляє onboarding-модель як дефолт для local-оточення лише тоді, коли відповідні env-змінні ще не задані зовні. Після цього збирає provider-контекст для `omlx`, додає base URL із завершальним слешем, щоб коректно працював URL-join, і запускає один запит у каскад. Тобто для бази `http://127.0.0.1:8000/v1` нормалізація гарантує роботу на шляху `http://127.0.0.1:8000/v1/`, а далі результат повертається як текст або як помилка рядком.

one_shot_acp не приймає рішення про fallback і не комбінує драбину доступності: він лише переводить запит у вибраного ACP-агента і виконує один сесійний виклик у заданому робочому каталозі. Вибір між `cursor` і `codex` тут жорстко обмежений, а всі інші значення відхиляються до того, як відбудеться будь-яка взаємодія з агентом. Якщо виклик не може бути виконаний через відсутність агента або підписки, помилка повертається назовні без прихованого переключення на інший канал.

## Публічний API

- one_shot — Один виклик локального/хмарного тиру каскаду через `genai`. `omlx_*` — онбординг-конфіг власника (baseUrl/model/apiKey), що йде в `local_providers` крейта під префіксом `omlx`.  # Errors Невалідний `tier`, відсутня конфігурація тиру (`N_LOCAL_*`/`N_CLOUD_*`), чи помилка самого виклику — усе як `Err(String)`.
- one_shot_acp — Один виклик через ACP — спавнить залогінений локально агентський CLI (`agent acp` чи `codex-acp`) і веде сесію по stdio/JSON-RPC у робочій директорії `cwd` (owner передає `tasksDir` вузла — природний «проєктний» корінь для ACP-сесії). Викликач (JS-драбина) вирішує, чи падати далі на [`one_shot`].  # Errors Невідомий `agent`, чи агент не встановлений/не залогінений підпискою.

## Гарантії поведінки

- Власних операцій запису (ФС/БД) у файлі немає; виклики імпортованих модулів можуть писати.
- Перехоплює помилки і не пропускає винятків назовні (fail-safe).
- За певних помилок повертає порожнє значення (напр. `null`) замість винятку.
