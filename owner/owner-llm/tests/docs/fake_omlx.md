## Огляд

FakeOmlxProvider доводить, що `owner_llm::one_shot` справді виконує HTTP round-trip проти налаштованого `omlx_base_url`, а не тихо обходить LLM-логіку й не звертається до реального провайдера. Для цього він піднімає локальний OpenAI-сумісний сервер на `127.0.0.1:0` з однією фіксованою відповіддю, щоб перевірка залежала саме від локального обміну через HTTP.

## Поведінка

1. Піднімає локальний fake OpenAI-сумісний LLM-сервер на еферемерному порту, щоб перевірка йшла тільки в межах процесу та не торкалась зовнішньої мережі.
2. Подає в `owner_llm::one_shot` конфігурований base URL цього сервера, фіксовану модель, системний контекст і користувацький запит, щоб підтвердити реальний HTTP round-trip через налаштований endpoint.
3. Повертає заздалегідь визначену відповідь асистента і очікує, що вона буде витягнута з HTTP-відповіді без обходу LLM-логіки.
4. Перевіряє, що при недоступному провайдері на `http://127.0.0.1:1` виклик завершується помилкою, а не panic, щоб зберегти fail-fast поведінку на зламаному з’єднанні.
