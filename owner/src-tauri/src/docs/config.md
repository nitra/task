## Огляд

Файл керує локальним owner-конфігом у `appLocalDataDir/config.json` у формі `{ "project_paths": [...], "identity": "handle" }`, а також персональними snooze-нагадуваннями. Він потрібен, щоб owner-застосунок знаходив робочі дерева через явний fallback-ланцюжок `owner config → app config com.nitra.task → ~/www`, але читав `identity` тільки з owner-конфігу, без fallback, щоб PII лишалась поза git.

Операції читання працюють fail-safe: за окремих збоїв повертаються порожні значення. Операції запису можуть повідомляти про помилку, якщо потрібні дані відсутні або конфіг не вдалося зберегти.

## Поведінка

`get_project_paths` читає список робочих дерев у стабільному fallback-ланцюжку: спершу власний `config.json`, потім конфіг основного app, далі домашній `~/www`. Відсутній файл, порожній список або нечитабельний вміст не зупиняють потік: такі джерела пропускаються як `absent.json` і `empty.json`, а перший корисний список на кшталт `full.json` стає результатом.

`set_project_paths` записує новий список у власний конфіг owner і зберігає решту локальних ключів без змін, щоб налаштування шляхів не скидало ідентичність або snooze-стан.

`get_identity` бере handle лише з власного конфігу owner. Fallback до app-конфігу або git-даних свідомо відсутній, бо ідентичність є локальним PII-налаштуванням власника.

`set_identity` оновлює локальний handle у власному конфігу; порожнє значення очищає ідентичність. Інші локальні налаштування при цьому не мають втрачатися.

`get_snoozes` повертає snooze-стан тільки для поточної ідентичності. Якщо ідентичність не налаштована, результат порожній, бо незрозуміло, чий персональний ритм читати. Прострочені записи не потрапляють у результат, а спільним у репозиторії лишається лише deadline.

`snooze_reminder` записує відкладення нагадування лише за наявності поточної ідентичності; без неї операція завершується fail-closed. Під час запису актуальний snooze-стан цієї людини оновлюється локально, а вже прострочені записи прибираються, щоб персональні нагадування не засмічували конфіг.

## Публічний API

- get_project_paths — Project paths власника: свій конфіг → конфіг app → `~/www`.
- set_project_paths — Зберігає project paths у власний конфіг owner (інші ключі не чіпає).
- get_identity — Handle власника з конфігу (None — ідентичність ще не налаштована).
- set_identity — Зберігає handle власника (порожній — скидає ідентичність).
- get_snoozes — Snooze-стан нагадувань поточної ідентичності: id нагадування → until (ISO 8601). Персональний ритм («коли мені нагадати») живе локально per-identity, не в git — спільним у репо лишається лише deadline (спека 260714, конституція п. 12). Прострочені записи відсіюються.
- snooze_reminder — Глушить нагадування до вказаного моменту — лише для поточної ідентичності (без неї fail-closed: чий ритм — невідомо). Заразом прибирає вже прострочені snooze-записи цієї людини.

## Гарантії поведінки

- Читання конфігу толерантне до відсутніх або нечитабельних джерел і використовує порожні значення там, де це безпечно.
- Запис snooze-стану явно повідомляє про помилку, якщо немає поточної ідентичності або конфіг не вдалося зберегти.
