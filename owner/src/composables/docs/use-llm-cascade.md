## Огляд

`useLlmCascade` забезпечує звернення до LLM-каскаду через мережу з fail-safe поведінкою: помилки перехоплюються, не виходять назовні, а для окремих збоїв повертається порожнє значення замість винятку. Це дає змогу викликати функцію без потреби окремо обробляти аварійні стани в місці використання.

## Поведінка

1. useLlmCascade надає стан для LLM-каскаду: зберігає налаштування local endpoint і моделі, а також окремий ключ доступу, який лишається порожнім, якщо його не заповнювали явно.
2. useLlmCascade відновлює базову адресу з локального сховища або бере стандартне значення http://127.0.0.1:8000/v1, щоб працювати без додаткового ручного налаштування після запуску.
3. useLlmCascade зберігає оновлені налаштування в локальному сховищі, але не зупиняє роботу, якщо сховище недоступне; у такому разі продовжує з поточним станом у пам’яті.
4. useLlmCascade для кожного звернення спочатку намагається пройти ACP-шлях лише тоді, коли це дозволено політикою автономності для конкретного вузла; якщо вузла або відповідного контексту немає, одразу переходить до local/cloud маршруту.
5. useLlmCascade формує один запит на відповідь: спершу пробує Cursor, потім Codex CLI, а якщо жоден ACP-варіант недоступний або не спрацював, звертається до local/cloud LLM через поточний omlx-конфіг.
6. useLlmCascade поводиться fail-safe: мережеві або інтеграційні помилки не виносяться назовні як винятки, а обробляються всередині, щоб виклик завершувався керовано.

## Публічний API

- useLlmCascade — Композабл каскаду LLM: конфіг local-тиру (omlx) + один виклик за драбиною.

## Гарантії поведінки

- Перехоплює помилки і не пропускає винятків назовні (fail-safe).
- За певних помилок повертає порожнє значення (напр. `null`) замість винятку.
